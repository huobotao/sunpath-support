Candidate-version tool documentation — not an App Store release announcement. Production iCloud/CloudKit configuration, final signing and testing on real devices have not been accepted yet. Availability can vary with the signed build, device, account, network and Apple services; this page does not promise that every feature works on every device.

NetPulse presents five views of network observations and optional test activity. It cannot read the system iCloud Photos or Drive upload queue, completion state, total data or remaining data. It cannot attribute observed bytes to iCloud or a particular app.

1. Overview

See the current network path, estimated device-interface upload/download rates, a chart of up to 60 recent samples, normally about once a second in the foreground and totals for the current sampling process. Link information can indicate a metered connection or Low Data Mode. The graph and totals describe the app's samples, not a carrier bill or a complete history outside the process.

2. Network

Inspect per-interface rates and link status. Loopback, AWDL and tunnel/VPN interfaces are shown separately and excluded from the app's combined estimate. This does not make the aggregate a perfect traffic meter: interfaces may overlap, counters can reset or be unavailable, and cellular counters may not update on some devices. Do not use a low reading as proof of no upload.

3. Activity

Read an activity label and its explanation based on estimated interface traffic, preferring the Wi-Fi interface and otherwise using the included-interface total. The recent activity count is a decaying sample count, not a duration of confirmed continuous upload. The traffic source remains unknown.

Photo-library statistics are optional. Choose “Allow counts of permitted photo items” only if you want this feature. Permission lets the app count only visible photo/video items and those created within the last 24 hours, without loading media. Limited access is not a count of your whole library. You can decline permission; neither the counts nor their changes prove iCloud sync progress.

4. Drive Test

Choose “Start iCloud Drive upload test” only when you are willing to use network data and cloud storage. The default test creates 8 MiB of random data in this app's own Drive container. The displayed progress belongs only to that generated file. Its average rate includes scheduling delay, and system progress may jump rather than update smoothly.

The current implementation stops observing if upload has not completed within 90 seconds and attempts cleanup. That timeout does not prove that the network or iCloud service failed, that a sent upload stopped, or that cloud data is already gone. Availability depends on the app's signed iCloud setup and your account.

5. CloudKit Test

In a configured version, “Start CloudKit upload test” starts a separate default 5 MiB random-data save to this app's CloudKit private database. Its result is payload size divided by total save duration, including setup and metadata overhead. Account availability is checked after you start; the app uses an in-memory CloudKit user-record identifier to check that cleanup still refers to the same account.

A message about missing container or environment configuration is a developer-build issue; repeatedly entering your password will not repair that build configuration. The Production container, schema and final signed entitlements remain to be verified. This page does not claim that CloudKit probes currently work on real devices.

Cancel and cleanup carefully

In Drive Test, “Cancel probe” requests cancellation and cleanup; in CloudKit Test, “Cancel this probe” requests cleanup after the current operation returns. Already-sent network operations may continue. Backgrounding requests cancellation, but the system may suspend the app before cleanup completes. Cleanup checks target only a file or matching record created by that probe.

If cleanup fails, use “Retry this app’s test file cleanup” in Drive Test or “Retry this probe’s cleanup” in CloudKit Test, within the same app process, before starting another probe in that module. Maintain the same account for CloudKit cleanup. Do not run repeated tests to try to clear an error: each test consumes data and quota, and an uncertain save may remain pending.

A force-quit, crash or restart loses the current in-memory cleanup tracking; cross-launch recovery is not implemented. Uninstalling is not a guaranteed way to remove cloud test data. If a residual-data problem persists after a restart, contact support. Do not delete unrelated documents or assume a reported cleanup instantly restores quota.

Before interpreting a result

Use the app in the foreground and consider network cost, low-power or background limits, available iCloud space and Apple service availability. The candidate has no automatic guarantee against cellular charges. Passive measurements do not measure your subscription speed; active probes describe only those generated test payloads. This tool does not diagnose which personal files are stuck or fix an iCloud backlog.

The planned release includes Simplified Chinese and English. Language support and all five views still require acceptance in the final signed version. This support page does not represent screenshots, device testing or review approval.
